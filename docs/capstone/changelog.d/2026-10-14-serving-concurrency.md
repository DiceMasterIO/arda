# 2026-10-14 — Serving concurrency and memory admission

- **arda-server / flight**: new `flight.rs`: per-key single-flight builds, cancellable gates and a request cancellation token set when a request future is dropped. Renders, pyramids, PNGs, tiles, JSON bodies and block compositions build once per key; concurrent requests wait for that build (review 3.6-1).
- **arda-server / lanes**: the request lane, the encode slot and every wait on another request's build are cancellable. A request whose client disconnects leaves the queue and starts no further stage; a stage already running finishes and caches its result, so bytes are unchanged (3.6-2).
- **arda-server / workers**: bake and prefetch jobs run under `catch_unwind`. A panicking bake fails its job with `internal`; a panicking prefetch job is dropped; both workers carry on (3.6-7).
- **arda-server / admission**: composed blocks are charged their vectors, string payloads and per-square `ext` maps (a MICRO town block: 3.0 MB, 0.64 MB before). At most 2 compositions run at once. The refine source decodes at most 6 areas per generation, then reopens the world, so decoded areas no longer pile up; query and relief share one base `World`. Startup admission adds the pipeline's bounds (2 x 192 MiB compositions, 256 refined blocks x 512 KiB, two refine generations, 64 town plans x 4 MiB: 1,132 MiB) and, once open, the measured library and textures, `society/` files, shore layer and an oversized plan, and refuses to start above 16 GiB (3.6-8).
- **Budgets trimmed** to keep the defaults admitted: decoded areas 1 GiB to 384 MiB (`--area-cache-mib`), derived layers 256 to 128 MiB, fine windows 512 to 256 MiB (`--fine-cache-mib`), encoded PNG, tile and body caches 256 to 160 MiB each. Defaults now admit 16,159 MiB of 16,384 with the MICRO society world. API.md, logic/16 §api-cache and 07-operations updated.
- **arda-server / prefetch**: cells warm nearest ring first, cardinal neighbours before diagonals (the 128-ppsq image slot no longer goes to the north-west diagonal), and a full queue lets its oldest waiting cells go for fresh ones (3.6-5, ordering and stale jobs; the double-cached render is not addressed).
- **Why**: review 3.6-1/2/5/7/8 and the admission note: duplicated pyramid builds, abandoned renders ahead of live ones, a dead bake worker after one panic, and memory held outside admission.
- **After (MICRO 42, release, society fixture)**: 16 concurrent cold 128-ppsq tiles on one cell: 16 pyramid builds and last tile at 6.1 s before, 1 build and 1.1 s after. A live tile behind three abandoned cold tiles: 2.8 s (5 renders) before, 1.45 s (3 renders: one abandoned render had already started) after. Idle RSS unchanged (about 675 MiB).
- **Tests**: `tests/world_api/serving.rs` (one pyramid for 16 concurrent tiles, an abandoned request leaves the queue, panicking bake and prefetch jobs), `tests/world_api/admission.rs` (town block charge includes `ext`, refined-block bound, refine-source generations answer like the full world, default config admitted with the measured world, startup refuses an over-ceiling world), unit tests in `flight.rs`, `admission.rs` and `prefetch.rs`.
