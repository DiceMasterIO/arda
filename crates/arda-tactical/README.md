# arda-tactical

This crate draws tactical battle maps on a 5-ft grid (goals 58–64). It has five parts:

- a JSON **asset catalogue** format;
- a **validator** for it;
- a **placeholder library** generated by code (207 assets covering every key in `docs/goal-prompts/vocabulary.md`);
- the **`TacticalLayout`** input type;
- a deterministic, parallel **compositor** with elevation shading, shorelines and a lighting pass.

The real art library will be painted outside this repository. It will work without code changes if it follows the format below.

```sh
arda tactical validate assets/tactical/placeholder        # check a library
arda tactical placeholders --out assets/tactical/placeholder [--seed 58]
arda tactical render --layout riverside --library assets/tactical/placeholder \
    --ppsq 128 --out out/tactical/riverside.png [--seed 1] [--grid] [--no-lighting] [--no-grade]
arda tactical render --layout all --out out/tactical       # every built-in layout
```

`--layout` takes one of these:

- the name of a built-in layout: `riverside`, `stone_warehouse`, `timber_house`, `wall_junctions`, `forest_glade`, `mountain_scree`, `marsh` or `farm_field`, or `benchmark` (the 64 × 64 performance map, not part of `all`);
- `all`;
- the path to a layout JSON file.

## Library directory

```
<library>/
  catalog.json          the catalogue (below)
  <any>/<path>.png      images named by each asset's `image`
```

The library is read at run time, so you can swap in a new directory without recompiling. Image paths must be relative and must stay inside the directory.

Images are 8-bit PNGs, usually RGBA; RGB and grey are also accepted. Alpha is straight, not premultiplied.

## `catalog.json`

```jsonc
{
  "format_version": 1,              // must be 1
  "library": "placeholder",         // short name
  "library_version": "0.1.0+seed58",// part of the render seed: new art, new variation
  "pixels_per_square": 128,         // source art resolution per 5-ft square
  "vocabulary": {                   // allowed values of the controlled tags
    "biome": ["temperate"], "culture": ["human"],
    "wealth": ["poor", "modest", "wealthy"],
    "function": ["house", "inn", "smithy", "warehouse", "street", "farm" /* … */]
  },
  "assets": [ /* asset records */ ]
}
```

The art is authored at `pixels_per_square`. The output resolution is a render option (`--ppsq`, 128 by default). Art is rescaled with premultiplied area averaging when it shrinks and with bilinear interpolation when it grows. Unknown fields are rejected everywhere.

### Asset record

| field | type | default | meaning |
|---|---|---|---|
| `id` | string | required | unique and stable, e.g. `prop.barrel` |
| `class` | `ground` \| `wall` \| `prop` \| `vegetation` \| `water` | required | the asset class |
| `image` | string | required | path relative to the library |
| `footprint` | `{"w": u32, "h": u32}` | required | size in squares before rotation; the image must be exactly `w·ppsq × h·ppsq` |
| `anchor` | `{"x": f32, "y": f32}` \| null | centre | pivot in squares from the image's top-left corner; a placement puts this point at its `x, y` |
| `rotations` | `[0, 90, 180, 270]` subset | `[0]` | allowed clockwise rotations; distinct values only |
| `mirror` | bool | false | whether a horizontal mirror is allowed; it is applied before rotation |
| `tags` | object | empty | `biome`, `culture`, `wealth` and `function` must appear in `vocabulary`; `free` is unchecked |
| `placement` | object | empty | dressing rules: `on_water`, `against_wall`, `near_road` (bools), `clearance_squares` (u8), `ground` (allowed ground keys; empty means any) |
| `blocks_sight` | bool | false | blocks line of sight |
| `blocks_movement` | bool | false | blocks movement |
| `difficult_terrain` | bool | false | its squares are difficult terrain |
| `cover` | `none` \| `half` \| `three_quarters` \| `total` | `none` | SRD cover level; `full` is accepted on input as an alias of `total` |
| `light` | `{"radius_ft": u16, "colour": [r, g, b]}` \| null | null | the light it emits (drawn as a warm pool) |
| `layer` | `ground` \| `water` \| `floor` \| `prop` \| `wall` \| `canopy` | required | render layer; see the draw order below |
| `z` | i16 | 0 | order within the layer; higher values draw later |
| `casts_shadow` | bool | false | whether the lighting pass casts a drop shadow for it |
| `height_ft` | u16 | 0 | height hint in feet; sets the shadow length (about 0.055 squares per foot) |
| `tileable` | bool | false | whether the texture repeats seamlessly (subject to the seam rule) |
| `ground` | string \| null | null | for `ground` and `water` textures: the key it paints, e.g. `grass` or `water_shallow` |
| `wall` | `{"kit": string, "role": role}` \| null | null | for `wall` assets: which kit it belongs to and its role in that kit |
| `provenance` | string | required | where the art came from (tool, prompt, author) |
| `licence` | string | required | the licence the art is used under |

### Classes and art conventions

**Ground and water.** These are opaque, seamlessly tiling textures. Tiles of `w × h` squares are typical; the placeholders use 2 × 2, and 4 × 4 for cobbles and flagstones, whose aligned layouts would otherwise repeat every two squares.

- Every texture with the same `ground` key is a **variant**. The compositor tiles them stochastically (see below): each warped cell of the world picks a variant and, for natural textures, a random offset into it, so no repeat is visible at map scale. Textures should therefore carry little broad, map-scale contrast of their own; the compositor adds a low-frequency macro tint.
- Variants of *structured* surfaces (cobbles, slabs, boards, rugs, furrows, cliff strata) must share one layout and differ only in tint, wear and stains, and must carry the free tag `structured`. The compositor keeps them aligned (no offsets) and only cross-fades variants; if their layouts differed, the cross-fade would show ghosted double grout lines.
- Water needs the keys `water_shallow` and `water_deep`. Depth below 5 ft reads as shallow and 5 ft or more as deep (the SRD wade/swim line, vocabulary I15), with a meandering margin between them.
- Textures are never rotated; `rotations` is ignored for them.

**Walls.** Walls sit on square *edges*, not in squares, because that is how line of sight works. A kit is every `wall` asset that shares a `kit` name. Every piece is 1 × 1 square, with the grid point or edge midpoint at the image centre.

- *Edge pieces* span one edge from vertex to vertex. They are drawn west to east through the image centre, and are turned 90° for vertical edges. Roles:
  - `run`
  - `door`
  - `window`
  - `gate`
- *Joint pieces* sit on a grid vertex. The compositor chooses one from the vertex's arm mask, rotating the canonical form clockwise until it matches. Roles and their canonical arms:
  - `corner`: east and south
  - `tee`: east, south and west
  - `cross`: all four
  - `end`: east only
  - `post`: east and west, on straight runs; optional

Every kit must provide `run`, `corner`, `tee`, `cross` and `end`. If a kit has several assets with the same role, one is picked per edge or vertex by hash.

**Props and vegetation.** These are cut-outs on a transparent background. The footprint covers the object; the anchor places it. Tree canopies use the `canopy` layer; low vegetation and rocks use `prop`. Floors laid over water, such as docks and bridges, use `floor`.

**No baked shadows.** Assets must not include cast shadows. The lighting pass derives shadows and occlusion from `height_ft`, `casts_shadow` and the layer. Form shading on the object itself (lit from the top-left, the compositor's sun) and outlines are fine and expected.

## Validator rules

`arda tactical validate` reports **every** issue as `<asset>: [<rule>] <detail>`. Kit-level issues are reported as `kit:<name>` and catalogue-level issues as `<catalog>`.

| rule | fails when |
|---|---|
| `format_version` | `format_version` ≠ 1, or `pixels_per_square` = 0 |
| `duplicate_id` | an `id` is already used |
| `unknown_class` | `class` is not one of the five classes |
| `unknown_tag` | a controlled tag is missing from `vocabulary` |
| `licence` / `provenance` | the field is empty |
| `rotation` | the list is empty, has duplicates, or holds a value other than 0, 90, 180 or 270 |
| `class_fields` | a ground or water texture has no `ground` key; a wall asset has no `wall`; a non-wall asset has one |
| `wall_kit` | a kit lacks `run`, `corner`, `tee`, `cross` or `end` |
| `image_missing` | the image is unreadable or its path leaves the library |
| `image_size` | the image is not `footprint × pixels_per_square` |
| `alpha_opaque` | a cut-out (wall, prop or vegetation) has no transparent pixels |
| `alpha_fringe` | more than 0.5 % of pixels are semi-transparent (alpha 1–239) *and* more than 2 px from an opaque pixel (haze, halos or glow); a normal anti-aliased edge passes |
| `texture_alpha` | a ground or water texture has any alpha below 255 |
| `tile_seam` | for `tileable` textures: the mean RGB difference across the wrap seams is more than 2 × the mean difference between interior neighbours |

## Layout (`TacticalLayout`)

A layout is JSON produced by serde. Coordinates are in squares, with (0, 0) at the top-left corner and y increasing to the south.

```jsonc
{
  "name": "riverside", "width": 30, "height": 17,
  "squares": [ {"ground": "grass", "elevation_ft": 0, "water_depth_ft": 0}, … ],  // row-major, width × height
  "walls": [ {"x": 19, "y": 7, "axis": "horizontal", "kind": "door", "kit": "stone"} ],
  "placements": [
    {"asset": {"id": "prop.crane"}, "x": 7.1, "y": 3.6, "rotation": 270, "mirror": false},
    {"asset": {"query": {"class": "prop", "tags": ["function:inn"]}}, "x": 8.6, "y": 0.6}
  ],
  "lights": [ {"x": 24.5, "y": 14.5, "radius_ft": 10, "colour": [255, 190, 110]} ],
  "origin": [640, 128]   // optional: world square of local (0, 0)
}
```

- A `horizontal` segment is the north edge of square (x, y). A `vertical` segment is its west edge. Use `x = width` or `y = height` for the far borders. If two segments share an edge, the later one wins, so a door can be punched into a run.
- `elevation_ft` is absolute feet above sea level, in 5-ft steps (vocabulary I20).
- A `query` placement picks, by hashing the seed and the placement index, among the assets of that class that carry every listed tag. Each candidate must allow the requested rotation. A tag such as `function:inn` or `biome:temperate` matches only that list (`biome`, `culture`, `wealth`, `function`, `free`); a bare tag such as `inn` matches any list. Free tags may themselves contain a colon (`craft:weaver`).
- `origin` (optional) places the layout in the world. With it, the compositor hashes and samples all noise at world coordinates, so separately rendered neighbouring blocks join without a seam, as long as each block is rendered with a margin of about six squares beyond the shared edge (elevation smoothing, warps and blends read that far).

## Compositor

`render(layout, library, seed, RenderOptions { ppsq, grid, lighting })` returns an RGBA image; `render_with(…, &Style { grade })` also controls the warm grade. The output is byte-identical for identical inputs. Every pixel is a pure function of the inputs computed with integer maths and IEEE `f32` `+ − × ÷`, `sqrt` and `floor` (no `sin`, `exp` or other libm calls); the per-pixel passes run in parallel over rows and column strips with rayon, which cannot change a result. The render seed is combined with `library_version`.

Draw order is **ground → water → floor → props → walls → canopies**, then lighting, the grade and the optional grid.

- **Ground.** Low-frequency fields (warps, tints) are evaluated every 8 or 16 px and interpolated. Each pixel's position is domain-warped by rotated value noise, and the warped position interpolates the per-square ground weights, which are roughened by per-key noise and sharpened (computed once per 2 × 2 block). Borders wander off the grid but never cross a wall.
  - *Stochastic tiling:* the world is cut into warped cells of 1.75 squares; each cell picks a variant and a texel offset; a narrow band at cell borders blends neighbours with a variance-preserving blend, so contrast is kept. Structured keys stay aligned.
  - *Transitions:* weights are height-blended with each texture's own brightness plus a cover class (vegetation over loose ground over hard surfaces), so tufts and stones poke across borders and grass creeps over paths; the lower side of a raised border gets a faint contact shade.
  - *Macro tint:* a smooth ±7 % brightness and hue drift at 6–9 squares breaks up map-scale repetition.
- **Elevation.** Square elevations are smoothed over a 5 × 5 window using only neighbours within 5 ft, so a grade stored as 5-ft steps becomes an even slope while cliffs of 10 ft or more stay sharp. The result is Catmull-Rom interpolated (continuous slope) through a gentle warp, on a 4-px grid.
  - a smooth hillshade from the top-left;
  - on real steps only (slope above about 1.25 ft per ft): a lit lip where the ground breaks over, a shaded foot, and 5-ft contour ledges (at 5k + 2.5 ft) that crowd into strata on tall faces;
  - elevation also feeds the shadow height buffer, so cliffs cast shadows.
- **Water.** The edge uses a lower-amplitude warp with a 1.5 px anti-aliased threshold, which keeps the bank line clean. Depth is interpolated on a wider warp: shallow texture below 5 ft, deep from 5 ft, darker still to 12 ft, sunlit shallows and a broken line of foam along the bank, and a band of wet soil on the land side.
- **Lighting** (masks at half resolution, upsampled bilinearly):
  - graded drop shadows from the top-left, taken from a height buffer (terrain plus asset heights capped at 12 ft): darkness grows with depth below the sun line, so shadows fade out towards their tips, then a three-pass box blur softens them;
  - tree canopies do not sweep: they cast a short, soft offset of their silhouette (about 0.45 of the crown radius), never darkening the crowns themselves;
  - ambient occlusion around props and walls, darker water along banks, and light pools.
- **Grade** (on by default, lighting only): 10 % desaturation, a warm cast that fades out in the highlights, a gentle contrast lift and warm shadows, to match the reference maps.

**Performance.** A 64 × 64-square map at 128 px per square (8192 × 8192 px) renders in about 1.5 s in release mode on a 32-thread machine under heavy load. Check it with

```sh
cargo test --release -p arda-tactical --test timing -- --ignored --nocapture
```

## Placeholder library

`arda tactical placeholders` regenerates `assets/tactical/placeholder` byte for byte from the seed; a test checks the committed copy. It holds 63 ground and water textures (28 keys, 2–3 variants each), 63 wall pieces (7 kits × 9 roles), 56 props and 25 vegetation assets, all Apache-2.0.

- *Ground* is painted on a wrapping brush tile: periodic rotated noise, hundreds of translucent dabs, grass tufts, pebbles, angular stones and wandering cracks, all toroidal so every texture passes the seam rule.
- *Cut-outs* are painted on a relief: colour, coverage, a height field and ink per pixel, then shaded from the top-left and outlined. Canopies are layered leaf clusters; rocks are irregular outlines with soft facets; nothing is painted outside a shape, so no shadow is baked.
- Props carry `function` tags for dressing queries (`function:inn` finds the bar counter, cask rack, tables and hearth; `function:smithy` the anvil, forge and grindstone) and workshop tools a `craft:*` free tag.
